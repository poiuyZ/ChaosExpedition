# Chaos Expedition 场景布局方案

> 状态：人工绘制方案，尚未写入地图。本文中的坐标、区域和场景元素均为提案，不代表地形、单位、装饰物或路径网格已经生成。

## 1. 检查结果与限制

### 地图尺寸和边界

- `maps/map/war3map.w3e` 的头部为 `W3E!`，版本 11，基础地形类型 `L`，未启用自定义 tileset；地形网格为 65×65，偏移为 `(-4096, -4096)`。头部及 65×65 个格式 11 地形记录与文件大小 29,644 字节相符。
- `maps/table/w3i.ini` 声明可玩地形尺寸 52×52。其镜头范围记录为 X `-2816..2816`、Y `-3328..2816`。
- `maps/map/war3map.j` 的 `SetCameraBounds` 范围是 X `-3328..3328`、Y `-3584..3072`，比 `w3i.ini` 声明的镜头范围更宽。两处配置不一致，须在编辑器中核对和统一。
- 本文暂用 X/Y `-2560..2560` 作为规划包络，确保规划点落在上述两组镜头范围的交集内。它不是已验证的实际寻路边界；最终坐标和地图边缘仍须在编辑器确认。
- 目标运行时为 Warcraft III 1.27b，但仓库模板和工具链文档主要标注 1.27a。版本兼容性未验证。

### 当前玩家起点

地图目前声明 4 个槽位，其中玩家索引 0、1 为真人，2、3 为电脑；JASS 也只配置索引 0..3。只读解析 `war3mapUnits.doo` 得到 4 个 `sloc` 起点，坐标与 `w3i.ini` 一致：

| 索引 | 当前类型 | 当前坐标 |
|---:|---|---:|
| 0 | 真人 | `(-512, -3328)` |
| 1 | 真人 | `(-320, 2432)` |
| 2 | 电脑 | `(-1088, -1792)` |
| 3 | 电脑 | `(1088, 1984)` |

要实现中央主城内六个清晰分开的玩家位置，方案将重新布置这四个起点，并新增两个；仅增加两个起点会使原有位置继续散落在地图各处，不符合中央出生区布局。最终须同时更新六个真人玩家槽位、起点列表和 JASS 初始化；本阶段未改动这些文件。

### 可生成性

- 随附 w3x2lni 工具链可用于 LNI 打包，但已检查的项目工具源码没有可用于本任务的、经过验证的 W3E 与 WPM 地形/路径网格生成及往返保真流程。
- `war3map.wpm` 为 65,552 字节；本阶段没有找到项目内经过验证的路径网格解析器/写入器，因此不对其内部尺寸、阻挡标记或通行结果作推断。
- `war3map.doo` 的记录没有经验证的项目内解析流程；不据此杜撰现有装饰物/障碍物 rawcode 或朝向。
- KKWE 可编辑 LNI 地图，但依照任务约束没有启动编辑器。未安装或验证外部转换器，也未写造二进制地图记录。

因此，本阶段仅能安全交付坐标与元素清单；实际地形、地貌装饰、障碍物及路径网格留待 KKWE 中人工编辑和验证。

## 2. 规划原则

1. 中央主城位于地图内侧，六个出生点绕开广场、商店和任务建筑。
2. 北、南、东、西四条路线从城市外围通往战斗区域，不穿越出生点。
3. 河流设置多处桥位；在 KKWE 中实际检查桥头可达性，不以河流中心线代替寻路验证。
4. 可破坏岩石仅为候选位置；不得将其作为唯一通路门闩。
5. 职业试炼集中在一处，留出多人同时通行空间；14 个方向入口仅为标记位置，不绑定未确认的职业 rawcode 或任务逻辑。
6. 地形贴图只使用地图当前 W3E 调色板中已确认的 ID；贴图视觉含义及装饰物资源需在编辑器内核实。
